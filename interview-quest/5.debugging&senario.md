These are probably the **highest-value questions for 6–7 YOE**.

### Scenario 1

> You have a shopping cart used across 20 components. How would you design the Redux state?

Follow-up:

> Would you store `cartTotal` in Redux?

> Two components need the same API data. Would you fetch it twice or store it in Redux?

---

> User navigates from `/users` → `/users/10` → `/users`. How would you avoid unnecessary API calls?

> The application has 50 Redux slices. How would you organize and maintain them?

### Scenario 5

> A component needs only `user.name`, but it re-renders whenever any property of `user` changes. How would you fix it?

# 10. Coding questions you should practice

For your experience level, I would expect coding exercises around these:

### A. Create a slice

```js
const userSlice = createSlice({
  name: "user",
  initialState: {
    data: null,
    loading: false,
    error: null,
  },
  reducers: {},
  extraReducers: (builder) => {
    // ...
  },
});
```

Implement API loading/success/error handling.

---

### B. Write a memoized selector

Given:

```js
todos: [
  { id: 1, completed: true },
  { id: 2, completed: false },
];
```

Create selectors for:

```text
all todos
completed todos
pending todos
completed count
```

---

### C. Debug unnecessary renders

Given a component using:

```js
const data = useSelector((state) => ({
  users: state.users,
  loading: state.loading,
}));
```

Explain why it can re-render and improve it.

---

### D. Implement optimistic update

Example:

```text
Like post
 ↓
Update UI immediately
 ↓
API request
 ↓
Success → keep change
Failure → rollback
```
